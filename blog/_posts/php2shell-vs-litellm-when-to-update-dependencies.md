10月21日、PHP は 2 件の重大な脆弱性、CVE-2026-109618 と CVE-2026-109619 の修正版を公開しました。どちらも CVSS v4.0 で 9.2 と評価されており、認証なしでリモートコードを実行される可能性があります。

CVE-2026-109618 は、メモリ不足の処理によって、内部のリクエストデータが部分的にしか初期化されていない状態で PHP が中断される問題です。CVE-2026-109619 では、リクエストに属する状態が、その基となるメモリの解放後もアクセス可能なまま残ることがあります。その結果、同じワーカーが処理する後続のリクエストから、古い状態が利用される可能性があります。

[PHP の勧告](https://www.php.net/archive/2026.php#2026-10-21-5)は、異例なほど明確でした。完全な緩和策はないため、更新が必要です。

修正版は PHP 8.2.35、8.3.36、8.4.27、8.5.12 です。PHP は、ソースからビルドしているユーザや LTS ベンダーを利用していないユーザ向けに、7.4、8.0、8.1 用の最小限のソースバックポートも公開しました。

Debian は同日 14:00:20 UTC に、[`php8.2` 8.2.35-1~deb12u1](https://tracker.debian.org/news/1813676/accepted-php82-8235-1deb12u1-source-into-oldstable-security/) を `bookworm-security` に受け入れました。その変更履歴には、両方の CVE に対する修正が記載されています。

## 固定したビルドを更新する

StableBuild は、[Debian、Ubuntu、Alpine のパッケージリポジトリを毎日スナップショットとして保存](https://stablebuild.gitbook.io/ja/mirrors-and-caches/os-package-registry-ubuntu-debian-alpine)しています。

修正版の Debian パッケージが公開される前のスナップショットには、以前のリポジトリ状態が保存されています。`8.2.35-1~deb12u1` を含むスナップショットが利用可能になったら、ピン止めする日時を新しいスナップショットの日付に進めて再ビルドし、テストできます。そのスナップショットを、新しい再現可能な基準として使用できます。

PHP2Shell の場合は、依存関係のセットを更新する必要があります。

## LiteLLM 1.107.0 が公開されていたのは 103 分間

同じ10月21日のこれより前には、LiteLLM はバージョン `1.107.0` を PyPI に公開していました。[LiteLLM のインシデントレポート](https://docs.litellm.ai/blog/security-incident-oct-21-2026)によると、このリリースの 7 つの wheel ファイルはすべて侵害されていました。

wheel は 11:39:51 から 11:40:13 UTC の間にアップロードされ、13:23 UTC までに削除されました。そこには、認証情報を盗むマルウェアと、リモートコード実行を可能にする仕組みが含まれていました。

LiteLLM によると、攻撃者は侵害した開発者の GitHub 認証情報を使ってリリースパイプラインを変更し、悪意のあるリリースを承認しました。GitHub の公式 `v1.107.0` ソースタグに問題はありませんでした。PyPI のアーティファクトは、攻撃者が管理するリポジトリからビルドされたものでした。

10月20日の StableBuild の [PyPI スナップショット](https://stablebuild.gitbook.io/ja/mirrors-and-caches/pypi-mirror)を使うビルドからは、`1.107.0` はまったく見えません。依存関係は、固定した日時のレジストリ状態に対して解決されるためです。

これは、依存関係のクールダウンが想定している事例です。新しく公開されたパッケージをビルドで利用できるようにするまで、一定期間待機させることができます。2 時間のクールダウンを設定していれば、`1.107.0` はまだ待機中であり、公開から 103 分後に PyPI から削除された時点でもビルドには取り込まれませんでした。

## ビルドに何が入る可能性があるかを把握する

StableBuild Enterprise では、SBOM のエクスポート、セキュリティスキャン、依存関係のクールダウンを利用できます。

SBOM のエクスポートは、ビルドに含まれる依存関係の一覧を提供します。セキュリティスキャンは、その一覧に脆弱性情報を追加します。依存関係のクールダウンは、新しく公開されたバージョンが利用可能になるまでの時間を制御します。

PHP2Shell では、既存の依存関係を修正版へ進める必要がありました。一方、LiteLLM `1.107.0` は新しいバージョンであり、PyPI で公開されていた短い時間に解決しない方が安全でした。

再現可能なビルドがあれば、どちらの場合も、変更前の状態を明確に把握できます。現在のビルドを生み出した依存関係を確認し、依存関係のセットを意図的に変更したうえで、その結果も再現可能な状態に保てます。

ビルドに取り込まれる依存関係をより細かく制御したい場合は、[StableBuild Enterprise についてお問い合わせください](https://www.stablebuild.com/contact)。
